# Core/Catalog

One table of 32 `ProgramSpec` values feeds three consumers: the renderer, the
system-prompt index, and the `choose_automaton` JSON-schema enum. A test
asserts the three agree, so they can never drift.

## Invariants

- Exactly **32** entries, unique ids, in the inventory's order.
- Behavior counts: **repetition 9, nesting 11, randomness 6, complexity 6**.
- Every id appears in `Catalog.ids`, in `Catalog.promptIndexLines`, and in the
  enum generated by `ToolSchemas`.

## Types

- `Behavior` — `.repetition`, `.nesting`, `.randomness`, `.complexity`.
- `Rating`→behaviors mapping (design doc §3.5):

  | Rating | Allowed behaviors |
  | --- | --- |
  | simple | repetition |
  | structured | nesting, repetition |
  | random | randomness |
  | complex | complexity |

- `GPUProgram` — `.elementary(rule:)` or `.totalistic(code:colors:)`; selects
  the step kernel and its constants.
- `Board` — `width`, `height`, `start` (`.center`, `.rightmost`,
  `.random(seed:)`). Widths/heights come from the inventory.
- `DisplayHints` — `stepsPerSecond`, `stepLimit`, `pinRight` (E110 only),
  `palette`.
- `Palette` — up to 16 colors; index 0 is the background. Elementary entries
  use white/black; totalistic entries white/gray/black (inventory §1.2).

## `look`

`ProgramSpec.look` is a one-sentence visual description derived from the
inventory's *Look* paragraph. It is the matching text in the prompt index and
must stay one line.

## `reference`

`ProgramSpec.reference` builds the CPU `RowProgram` for tests and the CPU
renderer. It is the only place that knows how a spec's `GPUProgram`/`Board`
map onto `ElementaryCA`/`TotalisticCA`.
